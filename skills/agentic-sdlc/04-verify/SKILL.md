# Verify (SDLC phase)

Use this skill when the user is **verifying** that work meets requirements: checking **acceptance criteria**, aligning with QA, or preparing **sign-off** before release.

## When to use

- "Verify against the PRD", "acceptance criteria", "QA checklist", "ready for release", "sign-off".

## Workflow

1. **Identify what to verify:** Feature, epic, or release; reference the PRD or Brief.
2. **Source requirements:** From the original PRD/Brief (Notion, doc, or summary) and any updated acceptance criteria.
3. **Compare:** Map implemented/delivered work to requirements; call out gaps or ambiguities.
4. **Checklist:** Build or walk through a short verification checklist (per story or per epic).
5. **Sign-off / next steps:** Suggest "ready for release" or "blocked on X"; point to **operate** for launch/runbooks if appropriate.

## Integration

- **Notion MCP:** Read PRD/Brief and any test or release pages.
- **Jira / Azure DevOps:** Read work item status and descriptions to confirm scope and completion.
- **reference:** Pull in org definitions of "done" or release criteria if available.
